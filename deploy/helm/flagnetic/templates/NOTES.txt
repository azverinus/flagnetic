Flagnetic {{ .Chart.AppVersion }} is installed as {{ include "flagnetic.fullname" . }}.

Create the first instance admin once, from a running pod:

  kubectl exec -n {{ .Release.Namespace }} deploy/{{ include "flagnetic.fullname" . }} -- flagnetic admin bootstrap --email you@example.com

It prints a password once. Then open the console:

  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "flagnetic.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}

and visit http://localhost:{{ .Values.service.port }}. Set config.base_url to the address the console is reached at.

Check the installation with: helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

{{- if not .Values.config.trusted_proxies }}

Traffic arrives through a proxy, and config.trusted_proxies is not set: the server then ignores X-Forwarded-For and sees every request as coming from the proxy, so all clients share one rate-limit budget and the audit log records the proxy's address. Set config.trusted_proxies to the Ingress controller's pod range or the Gateway's addresses. With a Service of type LoadBalancer or NodePort in front of the controller, externalTrafficPolicy: Cluster hides the client's address from it by source NAT; set Local, or the address the server learns is the node's.
{{- end }}
{{- end }}

{{- if lt (mul (int .Values.probes.startup.periodSeconds) (int .Values.probes.startup.failureThreshold)) 600 }}

migrations.mode is auto: the server migrates before it listens, waiting up to five minutes for the migration lock, and the startup probe allows only {{ mul (int .Values.probes.startup.periodSeconds) (int .Values.probes.startup.failureThreshold) }} seconds (probes.startup.periodSeconds times probes.startup.failureThreshold). A migration that outlives it is killed on every restart. Raise probes.startup.failureThreshold so the probe allows the lock wait and the longest migration, for example 400 with a period of 2 seconds.
{{- end }}
