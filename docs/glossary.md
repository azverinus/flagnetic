# Flagnetic glossary

This is the vocabulary of Flagnetic, a self-hosted platform for feature flags and experiments. The code, API, documentation and UI use these terms verbatim and avoid the alternatives listed under each term.

## Structure

**Instance**:
One running deployment of Flagnetic. It hosts one or more projects.
_Avoid_: server, installation, tenant

**Replica**:
One running process of an instance. Every replica of an instance is the same: it serves every API, holds every environment's ruleset and runs every worker, and replicas coordinate only through PostgreSQL.
_Avoid_: node, pod, server, leader

**Worker**:
Background work every replica runs in rounds, one round every interval, until the replica stops. A round that fails or panics is counted and the next round still runs; what keeps two replicas from doing one piece of work twice is the work's own locking in PostgreSQL, never the worker.
_Avoid_: job, cron, daemon, background task

**Drain**:
The window after a replica is told to stop in which it reports itself not ready, so that load balancers stop routing to it, while it still serves every request that reaches it. After the drain the replica stops accepting requests and shuts down.
_Avoid_: grace period (the bound on in-flight requests after the drain), cooldown

**Secret key**:
The instance-wide key, given as `FLAGNETIC_SECRET_KEY`. Every stored secret is sealed under it — encrypted so that only an instance holding the key opens it again — and sessions are signed with it. An instance keeps the key it was set up with: one stored **canary**, sealed under the key and opened on every start, proves the key still opens what the instance stored. Here, and only here, canary means that check.
_Avoid_: master key, encryption key, salt (reserved for the public bucketing salt)

**Project**:
The isolation boundary for flags, experiments, segments, environments and members. Nothing is shared across projects. Deleting a project removes everything in it except its audit entries, and frees its key.
_Avoid_: workspace, tenant, app, organization

**Environment**:
A named deployment target inside a project, such as production or staging. Every flag exists in every environment of its project; only its configuration differs per environment.
_Avoid_: stage, tier, env

**Protected environment**:
An environment whose ruleset changes only through a change request, whatever entity a write touches; the kill switch and import are the exceptions. Production is protected by default.
_Avoid_: locked environment, prod-only

**Member**:
A person who uses the management UI or API, working in each project through the grants they hold there. A member is invited until they set a password or sign in for the first time, active once they have, and deactivated when an instance admin offboards them; there is no deletion.
_Avoid_: user (reserved for the unit type), account, admin

**Invitation**:
The one-time link that lets an invited member set their first password. Its secret is shown once, to whoever issued it, and stored only as a hash; it expires, is used once, and is replaced by re-issuing. An owner's invitation to their project also carries a role there, granted when it is accepted; if that owner loses the owner role or leaves the project first, the role is dropped and the invitation still activates the member.
_Avoid_: invite code, activation link, signup link

**Password reset**:
The one-time link that lets an active member set a new password when they cannot sign in: requested by the member once mail is configured, or generated by an instance admin without it. Its secret is shown once, to whoever it was shown to, and stored only as a hash; it expires and is used once, and completing it revokes every other session.
_Avoid_: reset link, reset code, recovery link

**Mail**:
What the instance sends a member through the SMTP server an instance admin configures: an invitation, a password reset they asked for, or a test mail to the admin themselves. Mail goes out after the change that causes it is stored, and a send that fails never undoes that change. Without SMTP nothing is mailed, and the link is shown to the instance admin instead.
_Avoid_: email (the member's address), notification, message

**API token**:
The credential a member or a script presents to the management API as a bearer token. A personal access token acts for one member; a project token holds one fixed role in one project and dies with it. Scopes narrow what either may do and never add to it. Only a member signed in to a session creates one; no token creates another. Its value is shown once and stored only as a hash.
_Avoid_: API key, access key, bearer token, SDK key (reserved for SDKs)

**SCIM token**:
The credential an identity provider presents to `/scim/v2` to provision and deprovision members. Instance-wide, several may coexist for rotation; its value is shown once and stored only as a hash. It may be bound to the one auth provider that IdP signs members in through, the only provider at which the `externalId`s it writes link a sign-in and whose group mappings the SCIM groups it writes feed. One bound to no provider links nothing and its groups grant nothing.
_Avoid_: SCIM secret, provisioning key

**Session**:
A member's sign-in to the UI, held server-side and referred to by an httpOnly cookie. Every browser sign-in, whatever the method, ends in one; it ends at sign-out, revocation or timeout.
_Avoid_: JWT, auth cookie, session token

**Auth provider**:
One configured identity provider a member can sign in through, such as an OIDC or SAML integration. Its slug names it in a "sign in with" button and in its own redirect URI.
_Avoid_: SSO connection, identity source

**SSO enforcement**:
An email domain an instance admin sends to one auth provider: a password is no way in for an email in it, whether to sign in, to accept an invitation or to complete a password reset, and the sign-in page points it to that provider. Local login may also be disabled for everybody; `flagnetic admin unlock` lifts both.
_Avoid_: SSO-only domain, domain lock, forced SSO

**Group mapping**:
An auth provider's rule that a group in the identity provider's directory makes a grant of a role in one project, or instance admin. Every sign-in through the provider, and every change to a SCIM group, grants what the member's groups map to and takes away what they no longer do; the member's groups are those their last sign-in through the provider claimed together with their SCIM groups from that provider. A grant made by hand or by another provider is never touched, and the mapping's grant sits beside it.
_Avoid_: group sync, role mapping, SSO rule

**SCIM group**:
A group an identity provider pushes through `/scim/v2/Groups`, with the members SCIM provisions. It belongs to the auth provider its SCIM token is bound to, and its name is matched against that provider's group mappings alone, so joining, leaving, renaming or deleting it changes the roles its members hold without waiting for their next sign-in. A SCIM group no mapping names is kept and grants nothing.
_Avoid_: team, directory group, role group

**Identity**:
The link between a member and a subject at an auth provider, created the first time a sign-in through it resolves to that member, or when the member links it while signed in; unlinked by the member or an instance admin while another way in remains.
_Avoid_: external account, federated identity, SSO identity

**Auth method**:
One way a member can authenticate in a browser: their password or one of their identities. It is usable when local login accepts the password for their email, or the identity's auth provider is enabled; nothing removes a member's last usable one.
_Avoid_: login method, sign-in option, credential (the password alone)

**Assertion**:
The signed XML statement a SAML identity provider issues to say who signed in; consumed once, at the ACS, and never reaches the browser.
_Avoid_: SAML token, ticket

**IdP metadata**:
The XML document a SAML identity provider publishes naming its entity ID, SSO endpoint and signing certificates; fetched from a URL or pasted directly, refreshed automatically when fetched from a URL.
_Avoid_: IdP config, connection metadata

**SP metadata**:
The XML document this instance serves per SAML provider, naming its own entity ID, ACS endpoint and certificates, for an identity provider to import.
_Avoid_: SP config

**Certificate rotation**:
Replacing a SAML provider's SP key pair without breaking sign-in. Starting one generates the next pair beside the current one: the SP metadata lists both and an assertion encrypted for either is accepted, while AuthnRequests stay signed with the current key. Completing it, once the identity provider has re-imported the SP metadata, makes the next pair current and destroys the retired one.
_Avoid_: key rollover, cert renewal

**Role**:
A named set of permissions, which takes effect only through a grant in a project. Four are built in, owner, maintainer, developer and viewer: the release fixes what each holds, so a name means the same on every instance and nobody edits them. Any other role is a custom role, defined by an instance admin for the whole instance and granted per project. An instance admin holds every permission in every project without a grant.
_Avoid_: permission level, access group, policy

**Permission**:
One action a role allows, named after the action. A member's permissions in a project are the union of those of every grant they hold there: holding more grants never takes a permission away, and there is no deny.
_Avoid_: capability (what a caller may do once protection and the other rules are applied), scope (reserved for an API token), right, privilege

**Grant**:
One role held by one member in one project, made by hand or by an auth provider's group mapping, which owns it and replaces its grants as a set. A member may hold several grants in a project, from one source or several, and grants from different sources sit side by side. A caller may make or remove a grant only of a role whose every permission they hold there themselves.
_Avoid_: membership, assignment, role binding

## Flags

**Flag**:
A named, typed switch defined once per project. Its key is the same on every platform and in every environment.
_Avoid_: feature, toggle, gate, remote config key, parameter

**Flag type**:
The kind of value a flag serves: boolean, string, number or JSON.

**Variation**:
One of the named values a flag can serve. A boolean flag has exactly two; other types have as many as needed.
_Avoid_: variant, value, option, arm

**Rule**:
One ordered condition inside a flag's configuration for an environment. It decides which variation, rollout or experiment a context receives. Rules are checked top to bottom; the first match wins.
_Avoid_: strategy, gate, condition, targeting

**Fallthrough variation**:
The variation served when no rule matches.
_Avoid_: default (reserved for built-in defaults), fallback

**Off variation**:
The variation served when the flag is switched off in an environment.
_Avoid_: disabled value, kill value

**Kill switch**:
A single action that switches a flag off in an environment, serving its off variation to everyone. It bypasses change approval.
_Avoid_: emergency off, disable, panic button

**Revert**:
Returning one flag's configuration in one environment to exactly what it was at an earlier point in its history, discarding every change made to it since. It is a new change, not an erasure: the history keeps both what was reverted and the revert. It leaves the flag's definition and its segments as they are now. In a protected environment it goes through a change request like any other change, and that change request proposes only the earlier version.
_Avoid_: rollback (a database transaction's), undo, restore (restoring is bringing an archived flag back), roll back

**Rollout**:
Serving a variation to a percentage of units, deterministic per unit. Growing the percentage never moves a unit that was already in.
_Avoid_: gradual release, canary, ramp, percentage rule

**Override**:
A pinned variation for a specific unit ID in an environment, set through the platform, with an optional note saying why and the member who last wrote it. Overrides are marked in every event they influence and excluded from analysis.
_Avoid_: force, pin, whitelist, individual targeting

**Local override**:
A substitution of a flag value inside an SDK, on a developer's machine or a non-production build. It never reaches the server and is visibly marked as substituted.
_Avoid_: dev override, debug value, mock

**Owner**:
The member accountable for a flag or experiment: the person to ask before deleting it. Also the name of the built-in role holding every project permission, members and protection included; what the word is attached to says which is meant. Removing a member from a project is refused while they still own something in it.

**Flag state**:
What a flag's configuration in one environment serves at a glance: on or off, and whether it has rules, a rollout or an experiment. A list of flags shows one state per environment and is filtered by one within one environment.
_Avoid_: status, flag summary (summary is the evaluation summary)

**Stale flag**:
A flag past its expected lifetime, one that is no longer evaluated by any SDK, one whose owner is deactivated or holds no role in its project (nobody is left to ask before deleting it), or one bound to an overdue experiment.
_Avoid_: dead flag, zombie, tech debt flag

**Stale-flag digest**:
The `report.stale_flags` event naming a project's stale flags and overdue experiments with their reasons. It is sent weekly at a configured weekday and hour to every project with something stale, and to one project whenever a maintainer asks for it.
_Avoid_: stale report email, cleanup reminder, weekly report

## Targeting

**Context**:
The set of attributes describing the subject of an evaluation: one or more unit IDs plus derived, non-personal attributes such as platform or app version.
_Avoid_: user, actor, subject, principal

**Attribute**:
One named, typed value inside a context. Types include string, number, boolean, semantic version, date and list. A project declares its attributes; standard ones such as platform and app version are predeclared.
_Avoid_: property, trait, field, dimension

**Discovered attribute**:
An attribute seen in incoming contexts but not yet declared by the project. It is listed for a member to declare with a type, and cannot be used in rules until then.
_Avoid_: unknown attribute, dynamic attribute

**Condition**:
One comparison inside a rule or segment: an attribute, an operator and a value, membership in a segment, or a prerequisite. All conditions of a rule must hold for it to match.
_Avoid_: clause, predicate, constraint

**Prerequisite**:
A condition that another flag of the same project evaluates to a given variation for the same context.
_Avoid_: dependency, parent flag, gate

**Segment**:
A reusable, named, declarative set of conditions on context attributes.
_Avoid_: cohort, group, audience, list

**Private segment**:
A segment whose conditions and members never leave the server, such as a list of beta testers or a cohort of identifiers. Only server-side evaluation may use it. A client key learns the value a private-segment rule serves to a context it sends, and nothing about which rule served it.
_Avoid_: server-side segment, secret segment

## Units and identity

**Unit**:
The thing randomization is keyed on. A project declares its own unit types, for example user, device or anonymous visitor.
_Avoid_: actor, participant, entity, subject

**Unit type**:
One declared kind of unit in a project.

**Unit ID**:
The stable identifier of one unit of a given type.
_Avoid_: hash key, bucketing key, distinct id

**Alias**:
A recorded link between two unit IDs that belong to the same person, typically an anonymous ID and a user ID after sign-up.
_Avoid_: identify, merge, stitch, linking

**Bucket**:
A deterministic integer computed from a unit ID, a key and a salt by the published hashing formula. It contains no application secret and can be recomputed outside the platform.
_Avoid_: hash slot, partition

**Salt**:
A public, per-flag or per-experiment string mixed into the bucket computation. Visible in the UI so an analyst can recompute buckets.
_Avoid_: seed, secret

**Uniformity check**:
A chi-square test of how evenly the bucketing formula spreads a list of real unit IDs over the buckets, with an optional test that two salts' buckets are independent. Run before the first experiment, through the API or offline from the CLI (both named `hash-check`, after what they check); it records nothing.
_Avoid_: randomization check, A/A test

## Experiments

**Experiment**:
A time-boxed comparison of two or more variations of a flag on a declared unit type, with a hypothesis, an owner, traffic weights and a status.
_Avoid_: A/B test, test, split test, trial

**Traffic allocation**:
The share of units of the experiment's unit type that take part in it. Can only grow while the experiment runs; growing it never moves a unit already included.
_Avoid_: coverage, inclusion rate, sample

**Weights**:
The split of allocated traffic between an experiment's variations. Frozen once the experiment starts.
_Avoid_: ratios, percentages, distribution

**Assignment**:
The variation an experiment serves to a unit. Stable for the lifetime of the experiment.
_Avoid_: allocation, enrolment, bucketing

**Exposure**:
The event recorded when a unit actually encounters behaviour that depends on its assignment. Being assigned and being exposed are different things; analysis counts exposures. Every exposure carries an event ID chosen by the SDK so retries are dropped on receipt.
_Avoid_: impression, participation, view, hit

**First exposure**:
The earliest recorded exposure of a unit in an experiment. Sample-ratio checks and analysis are computed from first exposures; a later exposure with a different variation is a conflict and raises an alert.
_Avoid_: enrolment, entry

**Sample-ratio check**:
A chi-square test, every 10 minutes and once at stop, of each running experiment's first exposures per variation against its weights, in each environment holding its rule. Below 1000 first exposures, or when a variation expects fewer than 5, it is skipped. It raises an alert at p below 0.001 and clears it at p above 0.01. The statistic is documented so an analyst can reproduce it.
_Avoid_: SRM test, balance check (`srm` names only the alert kind and its events)

**Alert**:
A condition the check worker found on a running experiment, raised and later cleared by the worker itself: a sample-ratio mismatch (`srm`), no exposures for a day (`no_exposures`) or conflicts at the threshold (`exposure_conflicts`) in one environment, or running past its expected end (`past_expected_end`) for the experiment as a whole. Acknowledging it hides its banner until it clears; if the condition returns, a new alert is raised. Every raise emits its governance event once.
_Avoid_: incident, notification, warning

**Overdue**:
A running experiment whose expected end date has passed (`past_expected_end` in the API). It stays listed as overdue until it stops, and raises a `past_expected_end` alert once each time it crosses the date.
_Avoid_: expired, late

**Awaiting code removal**:
A stopped experiment whose flag SDKs still evaluate: evaluation summaries counted it in some environment within the last 7 days, and reported an evaluation there after the stop. Its code is still to be deleted.
_Avoid_: cleanup candidate, stale experiment

**Automatic exposure**:
A setting on a flag: with it, an SDK records an exposure after every evaluation whose result carries an experiment, instead of waiting for the explicit call. Every evaluation result carries the flag's setting, so the result alone says whether to record one.
_Avoid_: auto-tracking, implicit exposure, tracking callback

**Experiment status**:
One of draft (editable, not evaluated), running (weights frozen, traffic allocation may grow), stopped (a winner or the fallthrough replaces the experiment rule) and archived. There is no paused status: pausing an experiment is switching its flag off.

**Decision**:
What a stop records: outcome winner (with the winner variation, which replaces the experiment rule) or removed (which deletes it), and an optional note, editable afterwards while the experiment stays stopped. Kept forever, note aside, once recorded.
_Avoid_: resolution, verdict, outcome (reserved for the field naming winner or removed)

**Layer**:
A group of experiments whose audiences never overlap: a unit is in at most one experiment of a layer.
_Avoid_: namespace, mutex group, exclusion group

## Delivery

**Ruleset**:
The complete evaluable configuration of one environment at one moment, carrying a version. It is what SDKs download.
_Avoid_: config, snapshot, bundle, payload, manifest

**SDK key**:
The credential that identifies an environment to an SDK. A server key may receive private segments; a client key may not.
_Avoid_: API key, API token (both name the management API credential), token, secret

**Evaluation**:
Computing the value of a flag for a context. Local evaluation happens inside the SDK from a ruleset; remote evaluation happens on the server.
_Avoid_: resolution, lookup, check

**Evaluation reason**:
Why a value was served: matched rule, rollout, experiment, override, prerequisite failed, off, fallthrough, error, local override, or fallback. The last two are produced only by SDKs. A client key sees targeting match in place of matched rule, rollout, fallthrough and prerequisite failed, which tells it only that targeting decided the value.
_Avoid_: source, origin

**Unsupported rule**:
A rule holding an operator, condition kind or serve kind that an SDK's evaluator does not know, typically sent by a server newer than the SDK. The evaluator finds it when it decodes the ruleset; the SDK reports it once per flag and ruleset version, and wherever evaluating the flag reaches it, the flag serves the fallback with an error until the SDK is upgraded.
_Avoid_: unknown rule, invalid rule, broken rule

**Built-in default**:
The value compiled into the client application, used when no ruleset has ever been received.
_Avoid_: code default, hardcoded value

**Fallback chain**:
The order in which an SDK picks what to evaluate against: fresh ruleset, then last good ruleset, then built-in defaults.

**Propagation time**:
The time between saving a change and SDKs evaluating with it. For a mobile app it is declared separately for the foreground and for the next resume.
_Avoid_: TTL, latency, refresh interval

**Evaluation summary**:
Aggregated counts per flag, variation and evaluation reason that an SDK reports periodically, together with its version and platform. It carries no unit IDs.
_Avoid_: telemetry, usage stats, analytics, metrics

## Events and export

**Sink**:
A configured destination that receives a durable copy of events: ClickHouse, object storage or a webhook. Analysts work on sinks, never on the platform's own database.
_Avoid_: export target, destination, integration, connector

**Stream**:
One `(sink, event kind)` cursor: a sink with all three event kinds selected moves three streams, each at its own pace. Its cursor is an `(xid, seq)` position below which every row is either already delivered or never will be.
_Avoid_: subscription (reserved for a webhook subscription), channel, topic, position (as a field name; the word is cursor)

**In-flight batch**:
A stream's next batch, committed before it is sent and re-read identically, under the same delivery ID, until the target acknowledges it. What makes a resend after a crash indistinguishable from the first attempt to a receiver deduplicating on the ID.
_Avoid_: pending batch, outstanding batch

**Sink health**:
A sink's composed state: disabled, healthy, lagging, degraded, failing or stopped. Answered from its streams' live position and failure count, never cached from the last attempt.
_Avoid_: status

**Rejection**:
A target refusing a batch outright (a 4xx other than 408 and 429, or a ClickHouse exception saying the schema or the data does not fit): retried a bounded number of times, unlike a transient failure, which is retried without limit.
_Avoid_: permanent failure, hard failure, error

**Batch file**:
One batch of an object storage sink written as one object: JSON Lines (gzip, zstd or plain) or Parquet, keyed by its event kind, the UTC day of its first row's `received_at`, its project, its first and last `seq` and its delivery ID. The same rows always land at the same key, so a retry overwrites its own file; any other rows, even over the same range, get another file beside it, and consumers deduplicate by `event_id`.
_Avoid_: export file, dump, part, chunk

**Sink warning**:
What a test of a sink's stored configuration, or its enable, found that does not stop delivery: for ClickHouse, an optional column of the export schema a table lacks, which inserts skip. Replaced whole by the next test or enable.
_Avoid_: notice, lint, schema drift

**Dead letter**:
The record of an in-flight batch set aside after its rejections ran out: the stream's cursor range, the environments filter, attempts and last error, never the rows themselves. The cursor moves past it; a member redelivers it (under a new delivery ID, outside the stream's cursor) while its rows are still stored, or discards it.
_Avoid_: failed batch, poison message, DLQ

**Stopped sink**:
A sink the platform stopped on its own after several consecutive dead letters on one stream, taken as misconfiguration rather than a bad batch. No stream of it is claimed or starts another attempt, not even one claimed before the stop, and every cursor and in-flight batch holds until a member resumes it.
_Avoid_: paused, suspended, disabled (a member's choice, not the platform's)

**At risk**:
A sink one of whose streams has an undelivered row within the loss warning (`FLAGNETIC_EVENTS_LOSS_WARNING_HOURS`) of the retention edge: retention will drop it before delivery unless the sink recovers or retention grows. Shown alongside sink health, never instead of it; entering it emits `sink.at_risk` once.
_Avoid_: critical, overdue, warning (the word is reserved for a sink warning)

**Gap**:
The explicit record of rows a stream lost because retention dropped their partition while its cursor still pointed before them: the cursor range lost and when it was dropped. The cursor moves to just before the first row still stored and delivery continues; a member dismisses the gap once seen, and it stays listed.
_Avoid_: hole, data loss event, missing range

## Governance

**Change request**:
A proposed modification that waits for approval before it takes effect: of one flag's configuration in one environment; of one flag's or segment's definition (a flag's variations and automatic exposure, a segment's conditions and private switch) in every environment at once; or one experiment's start, stop or traffic allocation growth in every environment holding its rule at once. Its author, a member or a project token, cannot approve it, and only a member approves at all. It is superseded, and can no longer be applied, when what it was based on moves by any other write before it is applied: that configuration; for a definition, the flag or segment itself, or the configuration in any environment of that flag or of a flag referencing that segment; for an experiment, the experiment itself, or its flag's configuration in any environment holding its rule.
_Avoid_: PR, review, proposal, pending change

**Scheduled change**:
An approved change request that takes effect at a chosen future time instead of immediately.
_Avoid_: timer, cron, delayed release

**Schedule failure**:
The last failed application of a scheduled change, recorded on its change request: when, the error code and message, and how many consecutive attempts failed. After a set number the scheduler stops retrying it; the change request stays approved until cancelled, and a copy tries again. Stopped here means the scheduler gave up, not an experiment or a sink.
_Avoid_: error state, failed change request

**Audit entry**:
A record of who changed what, when, from which value to which. It outlives what it records, a deleted project included.
_Avoid_: history item, log line, changelog

**Actor**:
Who an audit entry names as having made the change, of one kind: a member, an API token (with the member who owns it), SCIM, an auth provider's group mapping (sso), the CLI or the system. The word is the audit log's alone; the subject of an evaluation is a context, and what randomization is keyed on is a unit.
_Avoid_: principal, initiator, who (as a field name)

**Webhook subscription**:
A project's standing request to be sent chosen events over signed HTTP, or an instance admin's for the audit entries that name no project. It names a target, the event types it wants and, optionally, the environments. Its secret is shown once, at creation or rotation, and signs every call made under it; for an overlap after a rotation the secret it replaced signs too. The platform disables one on its own after persistent failure, dropping what was pending, and only an enable, which resets its failure counters, clears that.
_Avoid_: hook, callback, integration, notification, sink (a sink carries exported events, not governance ones)

**Event**:
One thing that happened, sent to a webhook subscription as an envelope carrying its id, type, time, project, environment, actor, entity and data. Receivers deduplicate on the id; there is no ordering guarantee.
_Avoid_: notification, message, payload, hook (exposure and alias events are the Events and export section's, and never travel this way)

**Event catalogue**:
Every event type a webhook subscription may name, with what emits it and what its data carries. Most are derived from the audit entry of the change that causes them and name it; `audit.entry` is every entry itself, for export, and `*` means every type but that one.
_Avoid_: event list, topics, event registry

**Audit download**:
The audit entries a filter matches, streamed at once as JSON Lines or CSV up to a cap, for a reader without a receiver. A copy kept outside the platform is an `audit.entry` subscription instead.
_Avoid_: audit dump, report (the API calls it `…/audit/export`)

**Outbox**:
Where an event is written inside the transaction of the change it describes, so that a rolled-back change leaves no event and a committed one is delivered at least once.
_Avoid_: message queue, buffer, spool

**Change notice**:
One message of a project's management change stream, sent for every audit entry the project records: the entity it names, its environment and version, and the actor, never the entity's content, so the management client refetches what it shows. Its id is the audit entry's, which a reconnecting client resumes after; a client that cannot be caught up that way is told to refetch everything.
_Avoid_: event (a webhook subscription's), notification (PostgreSQL's NOTIFY that carries it between replicas), message, change event

**Delivery**:
One event sent to one subscription, carrying a status and every attempt made at it with its time, status code, latency and response snippet. A delivery keeps its id across its attempts; a redelivery is a new delivery of the same event, same event id and body, under a new id. A sink's own signed HTTP call reuses the same wire header (`X-Flagnetic-Delivery`) and the same at-least-once shape, for the same batch across retries, but it is a stream's in-flight batch, not this entry.
_Avoid_: send, call, dispatch, webhook (that is the subscription)

**Capability**:
One thing a caller may do, named after the action rather than after the role that allows it, and answered per project and per environment. The UI reads capabilities and never infers what to show from a role name.
_Avoid_: permission (reserved for what a role allows), grant (a role held in a project), scope (reserved for an API token)

**Minimum role**:
The weakest role that may call one operation, declared on the operation itself. An environment's protected attribute may raise it.
_Avoid_: required permission, access level
