# Flagnetic documentation

- [Installing Flagnetic](install.md): Docker Compose or the binary, TLS and a reverse proxy, PostgreSQL connections, upgrades.
- [Glossary](glossary.md): the vocabulary the code, the API, the docs and the console use.
- [Access](access.md): permissions, roles, grants, scopes and API tokens.
- [Flags](flags.md): flag definitions, configurations per environment, rules, rollouts, overrides, prerequisites, the kill switch, revert, copy and compare.
- [Experiments](experiments.md): an experiment's lifecycle, the rules serving it, salts and assignment, exposures, aliases across sign-up, alerts, and what a client key learns.
- [The sample-ratio check](sample-ratio-check.md): the statistic, when it is skipped, its two thresholds, a worked example and the warehouse SQL reproducing it.
- [Governance](governance.md): protected environments, which writes they refuse, and the kill switch exception.
- [Change requests](change-requests.md): proposing a flag's configuration for review, its diff and its states.
- [Webhooks](webhooks.md): subscribing a receiver to a project's events, its secret, the targets the platform calls, and the event catalogue.
- [Segments](segments.md) and [Targeting](targeting.md): reusable sets of conditions, and the operators and limits of every condition.
- [Operations](operations.md) and the [configuration reference](configuration.md): running the server, how changes reach SDKs across replicas, and what to watch.

## SDKs

- [Go SDK](../sdks/go/README.md), its [OpenFeature provider](../sdks/go-openfeature/README.md), and the [evaluator](../eval/README.md) every Go program shares.
- [Ruby SDK](sdks/ruby.md): the `flagnetic` gem with its Rails integration and test helper, and the `flagnetic-openfeature` provider.
- [Python SDK](sdks/python.md): the PyPI package `flagnetic`, its test helper and OpenFeature provider, and how it runs under pre-forking servers and asyncio.
- [JavaScript SDK](sdks/javascript.md): the npm package `flagnetic`, its server mode, browser client, React bindings and OpenFeature providers, and how soon each serves a change.
- [SDK keys](sdks/keys.md): server and client keys, rotation with an overlap, revocation, allowed origins, calls from browsers, and which SDKs use an environment.
- [Downloading the ruleset](sdks/ruleset.md): the server SDK's ruleset, its versions, conditional requests, compression and schema versions.
- [Remote evaluation](sdks/evaluate.md): served values for a context posted by an SDK that holds no ruleset, what each key learns, and the context's limits.
- [Events](sdks/events.md): evaluation summaries, aliases and exposures an SDK posts, each judged on its own and stored once.
- [The ruleset stream](sdks/stream.md): each new ruleset version as soon as a replica has it, heartbeats, reconnection and propagation.
- [Versioning and compatibility](sdks/compatibility.md): which server and schema versions each SDK version supports, and what a client key can learn.
- [Behaviour matrix](sdks/behaviour-matrix.md): which protocol scenario each SDK passes, generated by each SDK's own tests.
- [Implementing an SDK](sdks/conformance.md): the conformance suite in the order an SDK author works through it.
